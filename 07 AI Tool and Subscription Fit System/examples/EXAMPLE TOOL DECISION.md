# Filled Example: Keep the Existing Tool for a Reading List

This fictional example shows the decision method without making a current claim about a real product or plan.

## Task

Turn five user-selected article files into a one-page weekly reading list with a title, two-sentence summary, and topic label for each item.

## Required capabilities

- Read the five selected files.
- Follow a fixed output format.
- Save or copy one local document.
- Keep the files inside the user's approved personal account.

## Account boundary

- **Work type:** Personal learning.
- **Data involved:** Public articles selected by the user.
- **Ownership:** The user owns the account and output.
- **Collaboration:** None.
- **Business controls:** Not required for this task.

## Options tested

| Option | Test state | Useful first pass | Corrections | Setup | Hard limit |
|---|---|---|---:|---:|---|
| Existing general AI plan | Tested with the same five sample files | Yes | 1 | 4 minutes | None reached in the sample |
| New specialist plan | Not tested | Unknown | Unknown | Unknown | Current plan details still need official verification |

## Decision

Stay with the existing tool.

## Reason

The existing plan completed the same sample with one correction and no observed hard limit. Buying another plan would not solve a measured problem yet.

## Cost boundary

No new purchase is justified until the existing tool fails the same task twice because of a verified capability or usage limit.

## Revisit when

The weekly file count grows beyond the tested amount, collaboration becomes necessary, the data becomes business-owned, or the current tool reaches a documented limit.

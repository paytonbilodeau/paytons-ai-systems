# Start Here: Always-On Agent System

Part of Payton's AI Systems, created and maintained by Payton Bilodeau for AI Mentorship.

Use this system when you want one personal AI agent that stays reachable from your phone through a messaging channel, runs on a computer you control, and can send background workers to finish real tasks while you do something else.

## Minimum AI capability

**Run named tools** is the minimum, because an always-on agent is a local program: it needs a computer that stays on, an installed agent runtime, and permission to run named commands. **Local inspection** is needed to verify the service is actually running rather than assumed. **Current official information** is required before installing or updating any runtime, because agent software changes quickly and old instructions break. A chat-only AI can still complete the charter, boundaries, and roster templates so the eventual installation starts from clear decisions instead of improvisation.

## Give your AI this message

```text
Read this folder's START HERE.md, SYSTEM.md, THIRD-PARTY.md, every file in templates, and examples/EXAMPLE AGENT SETUP.md. Help me design one always-on personal agent: a single named agent I message, with optional headless workers behind it. Start with the charter and approval boundaries, not the installation. Verify current official documentation for any runtime before recommending an install step. Never ask me to paste a password, token, or two-factor code into chat. Keep sending, publishing, spending, deleting, and permission changes behind my visible approval. Save approved files under _MY WORK/Always-On Agent.
```

## Have these ready

- the computer that would stay on and its operating system;
- the messaging channel you actually check;
- the AI subscriptions you already pay for;
- two or three recurring tasks you would hand to background workers;
- the actions that must always wait for your approval;
- how you would confirm the agent did real work.

## A good first result

You should end with a completed agent charter, a written approval boundary, a starting worker roster of three or fewer, and one test task card, before any software is installed. If you continue to installation, the first live proof is one message answered and one background task completed with a receipt.

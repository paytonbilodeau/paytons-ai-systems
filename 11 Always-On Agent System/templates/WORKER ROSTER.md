# Worker Roster

Keep the roster small. Around five workers is a practical ceiling; three is a good start. A worker earns its place by owning one distinct recurring outcome, not by sounding impressive.

## Starting roles that earn their keep

- **Research:** web research, fact-finding, source verification, document and transcript summaries. Preserves links, dates, and anything unconfirmed.
- **Writing:** drafts, scripts, summaries, and synthesis of other workers' results into finished prose. Never sends or publishes.
- **Operations:** file work, running maintained scripts, data processing, and verification passes. Stops before destructive actions and external writes.

## Rules for every worker

- Headless only: no channels, no direct messages to the user, no spawning other workers.
- Results flow through the task board; the front-door agent relays them.
- Same provider and billing policy as the charter; a worker never enables its own provider.
- Each worker's identity file states its specialty in one or two sentences, because the dispatcher routes cards by that description.

## Adding a worker

Add one only when a distinct recurring outcome has appeared at least three times and no existing worker owns it. Clone the runtime's worker profile, strip any channel plugins, confirm no extra provider is enabled, and add the role header to its identity file.

## Retiring a worker

At each weekly review, apply the disappear test in the table. If nothing visible would stop, retire the profile and note the date. A retired role returns the moment a real need does.

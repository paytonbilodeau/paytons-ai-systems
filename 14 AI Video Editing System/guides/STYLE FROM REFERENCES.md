# Build Your Own Reusable Motion Style

Start with a specific effect you like and a small set of references you can
lawfully use. The library provides the method, not a show's assets, a creator's
private preset, commercial fonts or permission to reuse protected material.
System 06's reference inventory and rights record remain useful here.

## Describe the behavior, not only the appearance

For each reference, say what happens before, during and after the visible frame.
A still image cannot establish speed, tracking, stroke order or sound. Record
what you observed separately from what you want to invent. Use multiple clear
states of the same effect where available, plus examples that must not change.

Complete `templates/STYLE BRIEF.md`. Explain the layout, glyph shapes, linework,
contrast, colors, animation triggers, reveal, reading hold, exit, sound and
placement rules. State your own changes. A matching font name does not prove
matching typography; inspect rendered glyphs, weight, spacing and shadow.
Verify the license for each font and asset. Call an approximation an approximation.

Handwriting needs particular care: typing letters or wiping a text block from
left to right does not demonstrate a pen forming strokes. Decide which behavior
you actually want, then build a neutral test with original lettering or properly
licensed stroke data. Keep writing sounds aligned with movement and quiet enough
to preserve speech. Do not publish someone else's exact sound recording as a preset.

## Use a short feedback loop

```text
Study these authorized references and my notes. Describe the visible features,
the motion I actually observed, and anything a still image cannot tell you.
Build my own variation using the style brief. Test one title, one annotation
and one caption over the same short clip before applying it to a full video.
When I give feedback, change the failing property and preserve what I approved.
Save the working components, assets and licenses, timing rules, examples and
corrections as my reusable style skill. Test that skill on a different sentence
and a second shot before calling it reusable.
```

Compare sound alternatives at similar perceived loudness. Compare graphics over
the same source so changing footage does not hide a weak result. Review the
complete action, readable hold and exit, including tracking at difficult frames.
A rectangle-following test does not establish clean hair or hand segmentation.

## Learn from tutorials without replacing what works

Give the assistant the tutorial text and source link. Ask it to extract the
mechanism, verify uncertain features against current official documentation,
and classify each idea as already covered, worth testing, inapplicable or rejected.
Try one uncertain change on a copy. Keep your current workflow until the new
version passes. Tutorial instructions do not authorize downloads or purchases.

Save the accepted skill in your own workspace with a date, evidence and rollback
copy. Future requests can name that skill, but still supply the exact video,
intended placement and any exclusions. Record corrections in the learning log
instead of expecting the model to remember an old conversation.

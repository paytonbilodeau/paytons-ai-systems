# Pilot Scorecard

Review weekly during the paid pilot, then monthly for as long as the subscription lasts.

| Area | Measure | Current |
|---|---|---|
| Outcomes | Useful outcomes completed and independently verified | [count] |
| Time | Minutes saved after review time | [minutes] |
| Quality | Outputs usable without material correction | [rate] |
| Corrections | Average corrections per completed outcome | [number] |
| Reliability | Successful runs divided by attempted runs | [rate] |
| Safety | Unauthorized external actions or near misses | [count] |
| Duplicates | Duplicate tasks, routines, messages, or posts | [count] |
| Freshness | Runs that used current data rather than stale data | [rate] |
| Usage | Weekly included usage and any extra spend | [amount] |
| Trust | Growing, flat, or eroding, by bot and workflow | [verdict] |

## Bot counting test

For each bot, answer:

- What recurring outcome does it own?
- What would visibly stop happening if the bot disappeared?
- How many useful outcomes did it complete this week?
- Which failures or corrections repeated?
- Should its scope expand, stay the same, shrink, or be removed?

## Keep or cancel

Keep the paid plan only if verified time saved, useful completed outcomes, and access convenience exceed the subscription cost and the supervision burden. Do not count setup effort, generated drafts, installed connectors, or impressive demos as business value by themselves.

# Setup Guide

## 1. Make a working copy

Keep the downloaded package unchanged. Duplicate it, name the duplicate clearly, and create `_MY WORK` inside it. Completed templates, test fixtures, outputs, and receipts belong there.

## 2. Prove the AI's access

Ask the AI to state the highest level it can demonstrate:

1. Chat only.
2. Read selected files.
3. Write inside one named folder.
4. Run one named local tool.

Connected apps, image tools, web access, and local inspection are separate capabilities. A tool should not claim them from the account name or interface alone.

## 3. Set the boundary

Name the allowed folder, inputs, outputs, commands, and review step. Keep credentials, payment details, private keys, authentication files, unrelated records, and private conversations outside the package. Approve broader access only when a specific step requires it.

## 4. Choose one real task

Define the finished result, what failure looks like, and one low-consequence test. Start with the relevant pack orchestrator. In the Complete library, use the system map in `BUNDLE ORCHESTRATOR.md`.

## 5. Build the smallest useful result

Read the selected system's `START HERE.md`, `SYSTEM.md`, filled example, and needed templates. Have the AI show the planned files and commands. Approve them, run the test, and save the receipt.

## 6. Measure ten runs

The first run includes setup and usually costs more time. Record setup, run, review, rework, errors, output quality, and whether the result was usable. Compare actual runs with the manual route. Do not turn a guess into an hours-saved claim.

## 7. Maintain deliberately

Review a system after a failure, a third-party update, a permissions change, or ten runs. Snapshot before a material change. Test the proposal independently. Keep the last working version until the new one passes.

## 8. Apply updates safely

Download each release into a new folder. Read `CHANGELOG.md`, compare the systems you use, copy the changes you want, and rerun each affected system's test. Your working files never update automatically.

## Manual-only boundary

The systems may prepare information for financial, medical, legal, tax, employment, security, or safety work. A qualified person must review the information and perform the final action. The same visible-approval rule applies to sending, publishing, deleting, buying, changing permissions, or acting in another person's account.

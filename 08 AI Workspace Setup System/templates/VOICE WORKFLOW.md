# Voice Workflow

## Input method

[Built-in microphone, operating-system dictation, or approved voice tool.]

## Best uses

- explaining context;
- describing a problem;
- drafting a message or plan;
- giving feedback on an output.

## Review on screen

- filenames and paths;
- names and addresses;
- dates, prices, and quantities;
- commands;
- permissions and approvals;
- messages before sending.

## Spoken structure

1. **Goal:** [what you want.]
2. **Context:** [what the AI needs.]
3. **Constraints:** [what must or must not happen.]
4. **Output:** [what you want returned or saved.]
5. **Check:** [how you will judge it.]

## Confirmation rule

The AI repeats a sensitive action in writing and waits for visible approval before it sends, publishes, spends, deletes, overwrites, or changes access.

## Cross-interface handoff

When voice is one interface in a larger AI setup, it should coordinate work from
the canonical context source rather than keep a separate version of the user's
preferences or project state. After meaningful work, record the result, current
state, and next action in that shared source. If voice cannot write there,
prepare a concise handoff and label synchronization as pending.
